# UI 設計ルール（MIDI Kids Playground）

このプレイグラウンドでは、**ミニゲームやオプションが増えても「遊ぶ画面」と「鍵盤」が絶対に圧迫されないこと** を最優先の UI ルールとして定めます。

---

## 5つの基本原則

### 1. 常時表示は「3層構造」のみに固定する
画面の縦レイアウトは以下の 3 層だけとし、常設バーや固定ツールバーを追加しません。

```text
┌───────────────────────────────────────────────────┐
│ 1. トップバー（極薄 1 行固定 / 折り返し禁止）       │  ~44px
├───────────────────────────────────────────────────┤
│                                                   │
│ 2. メインステージ（flex: 1 で残り全面を占有）       │  主役
│    ※ゲームHUDやオプションは四隅にフローティング配置 │
│                                                   │
├───────────────────────────────────────────────────┤
│ 3. ピアノ鍵盤ドック（常に押しやすい高さを維持）     │  固定枠
└───────────────────────────────────────────────────┘
```

- **画面面積の 85% 以上** を「メインステージ + 鍵盤」にキープする。
- トップバーは `flex-wrap: nowrap` で **常に1行** を維持し、要素を増やさない。

### 2. メニュー・設定はすべて「オーバーレイ（ドロワー / シート）」に逃がす
- ゲーム一覧、音色、鍵盤レンジ、ドレミ表示、PCキー表示、MIDI デバイス選択、接続ガイドなどは **ドロワーやシートのオーバーレイ** に集約する。
- 項目がどれだけ増えてもオーバーレイ内がスクロールするだけで、背面のステージと鍵盤のサイズは **1px も変わらない** 構造にする。

### 3. ゲーム固有の UI はステージを削らず「フローティング」で載せる
- 各ミニゲームは上部に帯状のツールバーを置かない。
- スコアやコンボなどの HUD は **ステージ四隅に半透明フローティング配置** (`position: absolute`) とする。
- 曲選択・難易度・モード切替などのゲーム固有オプションは、ステージ右上の **設定チップ（`🎛️ ...`）から開くフローティングポップオーバー**、または開始前オーバーレイ内に収める。

### 4. 通知・案内バナーでレイアウトを押し下げない
- iPad 案内や音声有効化ボタンは、画面を押し下げる常設バナーにしない。
- 音声未解除のガイドは **ステージ上のフローティングボタン** として表示し、解除後は即座に消える。
- MIDI 接続状態や iPad ガイドはトップバーの小さなステータスチップからモーダルで開けるようにする。

### 5. 「子どもの操作面」と「大人の設定面」を分離する
- **子どもが触る場所**: メインステージ・鍵盤・最小限のワンタップ操作（開始・お手本）。
- **大人が調整する場所**: 右上の `⚙️` 設定ドロワーと、ゲーム内の `🎛️` 設定ポップオーバー。
- 誤タップで設定画面やスクロールが暴発しないよう、プレイ面の要素数は最小限に保つ。

---

## 新しいミニゲームを作るときの UI チェックリスト

`src/games/` に新しいゲームを追加するときは、以下を守ってください。

- [ ] ルート要素は `position: relative; width: 100%; height: 100%;` でステージ全面を使う
- [ ] 上部に固定の `.game-toolbar` を作らず、HUD は `.stage-hud-top`（`position: absolute; pointer-events: none;`、ボタンのみ `pointer-events: auto`）に載せる
- [ ] オプション項目が 3 つ以上ある場合は `.stage-popover` 内に収める
- [ ] iPad 横向き（例: `1024x768` / `1180x820`）および縦向き・スマホ幅でもスクロールが発生せず、ステージと鍵盤が収まることを確認する
